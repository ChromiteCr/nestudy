# S4 阶段设计（已批准）

> 批准日期：2026-07-20。范围：Reflection Studio（AI 采访式反思）+ OPFS 附件（单图）+ 星图卫星接入。

## 立意与关键决策（来自用户）
- 触发场景三选全要：关联到具体活动 / 独立日记式反思 / 主动 Agent 提醒触发。
- 交互形式：**独立采访视图**（Reflection Studio），不复用主聊天界面，保持沉浸感。
- 采访流程：固定 STAR 式问题模板，用户可选"直接进 AI 采访"或"自己先写草稿"（草稿路径 AI 仍按模板追问未覆盖的点，但允许发散到草稿提到的话题）。
- 多媒体：**S4 只做单张图片**，本地 OPFS 存储，不做任何 AI 分析、不上传。预留 `uploadToAiServer` / `uploadToOwnServer` 两个 stub 接口（S5/S7 填实现），数据结构按"多文件/多类型"设计以避免未来迁移。
- 星图接入：反思节点作为**卫星**，3D 基准坐标 = 关联活动坐标 + 小半径偏移，复用现有旋转/投影管线；反思中提到与其他活动的联系，AI 一并提议叙事线边。独立反思无关联时先放外层未分类区。
- 架构底线不变：**AI 不直接写库**，采访结束在 Studio 内出确认卡（可编辑总结、可勾选/取消建议的边），确认后才入库。

## 1. 数据模型（Dexie v5）

```ts
export type ReflectionTrigger = 'activity' | 'freeform' | 'agent'
export type ReflectionAttachmentKind = 'image'

export interface ReflectionQA {
  question: string
  answer: string
}

export interface ReflectionAttachment {
  id: string
  kind: ReflectionAttachmentKind
  ref: string   // OPFS 文件引用
}

export interface Reflection {
  id: string
  title: string
  trigger: ReflectionTrigger
  activityId?: string          // freeform/agent 触发可为空
  qa: ReflectionQA[]
  summary: string
  attachments: ReflectionAttachment[]   // S4 UI 限 1 张图片，结构不限，S5 放开
  source: DataSource
  createdAt: number
}
```

`reflections` 表（Dexie v5）：`id, activityId, createdAt`。
节点 id 前缀延续 S3 约定：`reflection:<id>`。

## 2. 存储层：OPFS + 预留上传接口

- `src/lib/storage/opfs.ts`：
  - `saveAttachment(file: File): Promise<string>` 写入 OPFS，返回 ref
  - `getAttachmentURL(ref: string): Promise<string>` 读出生成本地 object URL
  - `deleteAttachment(ref: string): Promise<void>`
  - 全部纯本地读写，不联网
- `src/lib/attachments/upload-targets.ts`：
  - `uploadToAiServer(ref: string): Promise<never>` / `uploadToOwnServer(ref: string): Promise<never>`
  - 函数体直接 `throw new Error('尚未实现')`，只定形状，UI 不暴露调用入口
- 特性检测：`navigator.storage?.getDirectory` 不存在时，附件按钮直接隐藏，反思照常纯文本可用

## 3. 采访引擎

不复用主聊天的 agent 工具调用循环（那是给带 propose_* 卡片的主助手设计的）。改用类似 `graph-ai.ts` 的**轻量一次性/多轮 completion**，无函数调用：

- 固定模板（STAR 式，6 题）：做了什么 / 你的角色 / 最大挑战 / 学到什么 / 与其他经历的联系 / 接下来的打算
- **AI 采访路径**：逐题问，用户答，每题答后调一次 DeepSeek 判断"追问细节还是进下一题"；6 题问完进入总结
- **草稿路径**：用户先在文本框自由写 → AI 判断草稿覆盖了模板哪些点（不严格对应）→ 对未覆盖/可深挖的点追问，追问允许发散到草稿提到但模板没有的话题
- 结束后统一调一次总结生成：输出 `{ summary, edges: ProposedEdge[] }`（`ProposedEdge` 复用 S3 已有结构），Studio 内部确认卡展示，可编辑总结文字/勾选边，确认后一次性写入 `reflections` + `narrativeEdges` 表
- 采访中 AI 调用失败：给"重试"按钮，已答内容是本地 state 不丢失
- 模板路径至少答满 6 题才能进总结；草稿路径不设最低字数，内容太少时 AI 在追问里自然引导

## 4. 星图卫星渲染

`sphere-model.ts` 新增一步：反思节点基准坐标 = 关联活动节点基准坐标 + 小半径偏移（同一套旋转矩阵/投影，天然呈现"卫星绕活动转"）。反思节点视觉上比活动节点更小更暗，避免抢主星视觉重量。无关联的独立反思（`activityId` 为空）先放外层未分类区，建立关联/叙事线后再迁移过去。

## 5. 导航与入口

- `AppView` 新增 `'reflection'`，侧栏加"反思"导航项，主界面为 Reflection Studio（反思列表 + 开始新反思）
- 入口三处：
  1. Studio 内"开始新反思"按钮（独立日记路径）
  2. 活动列表/详情卡片加"反思一下"按钮，跳转 Studio 并预填 activityId
  3. Dashboard 主动提醒卡（见第 6 节）
- 跨视图预填复用 S2 已有的 `pendingPrompt` 模式：新增轻量 `pendingReflectionActivityId` 状态，点击"反思一下"写入，Studio 挂载时消费并清空

## 6. 主动 Agent 触发规则

`lib/engine/rules.ts` 声明式规则引擎新增一条：活动 `endDate` 已过去 ≥ 7 天且该活动没有任何关联反思 → Dashboard 提醒卡"要不要反思一下『XX』？"，点击跳转 Studio 并预填。只对已结束活动（`endDate` 非空）触发，进行中的活动不打扰。

## 7. 版本节奏

S4a 数据模型 + OPFS 存储层 → S4b 采访引擎 + Studio UI → S4c 星图卫星接入 + 叙事线联动 → S4d 主动 Agent 触发规则 + 入口联动 → 阶段完成升 **S4**。
