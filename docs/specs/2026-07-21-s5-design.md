# S5 Skill 系统（精简设计）

> 用户要求本阶段精简规划、减少 token 消耗，故本 spec 保持简短。

## 硬性原则（沿用既有决策）

能用 skill 表达的不做成平台功能。S5 只做「声明式 skill 引擎骨架」+「打通一个官方 skill 的全流程」，其余官方 skill（What-if、作品集导出等）留给 S5a/S5b 用同一格式补。

## 数据格式：纯 JSON 声明

```ts
interface SkillDefinition {
  id: string
  name: string
  description: string
  /** 激活后注入 agent loop system prompt 的人设片段 */
  personaPrompt: string
  /** 激活时允许调用的工具名（AGENT_TOOLS 的子集），收窄工具面避免误写库 */
  allowedTools: string[]
  /** 规则引擎建议话术里引用的一句话说明（可选） */
  suggestHint?: string
}
```

Skill 定义存为 `src/lib/skills/defs/*.json`，`registry.ts` 静态 import 汇总，导出 `listSkills()` / `getSkill(id)`。纯数据、不含可执行代码——为 S6 开源 skill 市场接受社区贡献做准备（贡献者提交的是数据，不是代码，没有供应链风险）。

## 第一个官方 skill：招生官读档（`admissions-reader`）

- `allowedTools`: `['get_profile', 'get_activities', 'get_reflections']`（只读，不含任何 `propose_*`）
- `personaPrompt`: 让模型扮演资深顶尖大学招生官，读档后给出优势/短板/建议的点评
- 输出：直接作为聊天文本回复，不生成确认卡（纯建议性质，无需入库）

## 执行机制：复用 S2 agent loop，不新建一套

- 新 store `useSkillStore`：`activeSkillId: string | null`，`setActiveSkill(id)`
- `chatStore.runAgentLoop` 组装 system prompt 时：若有 `activeSkillId`，追加对应 `personaPrompt`；调用 `provider.streamChat` 时的 `tools` 从 `AGENT_TOOLS` 按 `allowedTools` 过滤
- 聊天页顶部小状态条：有 `activeSkillId` 时显示「当前 Skill：招生官读档」+ 退出按钮（`setActiveSkill(null)`）

## 触发：手动 + 规则引擎建议（复用 pendingPrompt 机制）

- 手动：聊天页一个「使用 Skill」入口（下拉选择 `listSkills()`），选中即 `setActiveSkill`
- 主动：`rules.ts` 新增 R6——活动数 ≥3 且从未用过 `admissions-reader` 时命中；`Reminder` 新增 `suggestSkillId?: string` 字段（与 `prompt`/`reflectActivityId` 三选一）
- `DashboardView.handleReminder` 新增分支：命中 `suggestSkillId` 时 `setActiveSkill(id)` + `setPendingPrompt('帮我做一次招生官读档')` + 跳转聊天页——和 S4 反思入口是同一套接线方式

## 不做的（YAGNI）

- 不做 skill 市场/远程加载（S6）
- 不做多 skill 组合/链式调用
- 除只读分析类 skill 外，不做导出类/写库类 skill 的通用机制（等真正需要作品集导出时再设计）

## 验收

- `npm run build` 通过
- 浏览器实测：手动选择「招生官读档」→ 发消息 → 收到基于真实档案/活动/反思数据的点评，且过程中模型没有调用任何 `propose_*` 工具
- 造出满足 R6 条件的数据 → Dashboard 出现建议卡 → 点击「去处理」→ 自动激活 skill 并带 prompt 跳转聊天 → 出结果
